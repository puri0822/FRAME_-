# 요리조리 (Yorijori) — 소프트웨어 요구사항 명세서 (SRS)

**버전**: 1.0  
**작성일**: 2026-04-18  
**플랫폼**: React Native / Expo (iOS · Android · Web)

---

## 1. 문서 개요

### 1.1 목적
본 문서는 냉장고 재료 관리 및 레시피 추천 앱 **요리조리**의 기능 요구사항(FR) 및 비기능 요구사항(NFR)을 정의한다.

### 1.2 범위
- 사용자 인증 (로그인 / 회원가입)
- 냉장고 재료 관리
- 레시피 탐색 및 검색
- AI 채팅 기반 레시피 추천

### 1.3 용어 정의

| 용어 | 정의 |
|------|------|
| 재료 | 냉장고에 등록되는 식자재 단위 (이름 + 카테고리 + 유통기한 + 수량) |
| 임박 재료 | 유통기한이 D-3 이내이거나 이미 만료된 재료 |
| 레시피 | 요리명, 재료 목록, 조리 단계, 난이도, 조리시간을 포함하는 요리 정보 단위 |
| 트렌딩 | SNS 기반 인기 레시피 순위 데이터 |

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 인증 (AUTH)

#### FR-AUTH-01 로그인
- 이메일 + 비밀번호 입력으로 로그인
- 이메일은 정규식 검증 (`/^[^\s@]+@[^\s@]+\.[^\s@]+$/`)
- 로그인 성공 시 `/(tabs)/home`으로 이동
- Google · Apple 소셜 로그인 버튼 제공 (현재 UI만)

| ID | 요구사항 | 우선순위 | 현재 상태 |
|----|----------|----------|-----------|
| FR-AUTH-01-1 | 이메일·비밀번호 미입력 시 경고 Alert | Must | 구현됨 |
| FR-AUTH-01-2 | 이메일 형식 오류 시 경고 Alert | Must | 구현됨 |
| FR-AUTH-01-3 | 로그인 성공 후 홈 화면 이동 | Must | 시뮬레이션 |
| FR-AUTH-01-4 | Google / Apple OAuth 소셜 로그인 | Should | 미구현 |
| FR-AUTH-01-5 | 로그인 상태 영속화 (앱 재시작 유지) | Must | 미구현 |

#### FR-AUTH-02 회원가입
- 입력 필드: 이름(2자↑), 이메일, 비밀번호(6자↑), 비밀번호 확인, 약관 동의
- 유효성 실패 시 Alert로 구체적 오류 안내
- 회원가입 완료 시 `/auth/login`으로 이동

| ID | 요구사항 | 우선순위 | 현재 상태 |
|----|----------|----------|-----------|
| FR-AUTH-02-1 | 이름 2자 미만 시 오류 | Must | 구현됨 |
| FR-AUTH-02-2 | 비밀번호 6자 미만 시 오류 | Must | 구현됨 |
| FR-AUTH-02-3 | 비밀번호 확인 불일치 시 오류 | Must | 구현됨 |
| FR-AUTH-02-4 | 약관 미동의 시 오류 | Must | 구현됨 |
| FR-AUTH-02-5 | 실제 서버 계정 생성 | Must | 미구현 |

### 3.2 냉장고 재료 관리 (FRIDGE)

#### FR-FRIDGE-01 재료 추가
- 재료명, 카테고리(5종), 유통기한(YYYY-MM-DD), 수량 입력
- 유통기한 단축 버튼: +1일 / +3일 / +7일 / +30일
- 이름 + 카테고리 조합 중복 시 추가 방지

| ID | 요구사항 | 우선순위 | 현재 상태 |
|----|----------|----------|-----------|
| FR-FRIDGE-01-1 | 재료명 미입력 시 등록 불가 | Must | 구현됨 |
| FR-FRIDGE-01-2 | 카테고리 5종 선택 (채소/과일, 육류/수산, 유제품, 가공/편의점, 양념) | Must | 구현됨 |
| FR-FRIDGE-01-3 | 유통기한 +N일 단축 버튼 | Should | 구현됨 |
| FR-FRIDGE-01-4 | 수량 스텝퍼 (최소 1 ~ 무제한) | Should | 구현됨 |
| FR-FRIDGE-01-5 | 이름+카테고리 중복 추가 방지 | Must | 구현됨 |
| FR-FRIDGE-01-6 | 카메라로 재료 자동 인식 | Could | 미구현 |

#### FR-FRIDGE-02 재료 삭제
- 재료 카드의 × 버튼으로 즉시 삭제 (확인 없이)

| ID | 요구사항 | 우선순위 | 현재 상태 |
|----|----------|----------|-----------|
| FR-FRIDGE-02-1 | × 버튼 탭으로 재료 즉시 제거 | Must | 구현됨 |
| FR-FRIDGE-02-2 | 삭제 전 확인 다이얼로그 (옵션) | Could | 미구현 |

#### FR-FRIDGE-03 재료 필터 및 표시
- 탭 필터: 전체 / 임박 🚨 / 카테고리별 5종 (총 7탭)
- "전체" 탭: 카테고리별 그룹 헤더 포함 표시
- "임박 🚨" 탭: D-3 이내 및 만료 재료만 표시

| ID | 요구사항 | 우선순위 | 현재 상태 |
|----|----------|----------|-----------|
| FR-FRIDGE-03-1 | 전체 탭 카테고리 그룹화 | Should | 구현됨 |
| FR-FRIDGE-03-2 | 임박 탭 D-3 이내 + 만료 필터 | Must | 구현됨 |
| FR-FRIDGE-03-3 | 카테고리별 탭 필터 | Should | 구현됨 |
| FR-FRIDGE-03-4 | 유통기한 색상 구분 (만료: 빨강, 임박: 주황, 정상: 회색) | Should | 구현됨 |

#### FR-FRIDGE-04 재료 영속화

| ID | 요구사항 | 우선순위 | 현재 상태 |
|----|----------|----------|-----------|
| FR-FRIDGE-04-1 | AsyncStorage로 재료 데이터 로컬 저장 | Must | 미구현 |
| FR-FRIDGE-04-2 | 앱 재시작 후 재료 목록 복원 | Must | 미구현 |

## 4. 비기능 요구사항 (Non-Functional Requirements)

### 4.1 성능

| ID | 요구사항 |
|----|----------|
| NFR-PERF-01 | 화면 전환 응답: 300ms 이내 |
| NFR-PERF-02 | AI 응답 시뮬레이션 딜레이: 800~1500ms (체감 자연스러움) |
| NFR-PERF-03 | 재료 목록 최대 200개 이상에서도 스크롤 버벅임 없음 |

### 4.2 사용성

| ID | 요구사항 |
|----|----------|
| NFR-UX-01 | 탭 바 3개 탭으로 주요 기능 1 depth 이내 접근 |
| NFR-UX-02 | 유통기한 만료 상태를 색상(빨강/주황/회색)으로 즉시 식별 가능 |
| NFR-UX-03 | 빈 상태(Empty State) 시 안내 텍스트 및 아이콘 표시 |
| NFR-UX-04 | iOS / Android / Web 3개 플랫폼 정상 동작 |

### 4.3 신뢰성

| ID | 요구사항 |
|----|----------|
| NFR-REL-01 | 재료 데이터 로컬 저장으로 네트워크 단절 시에도 조회 가능 |
| NFR-REL-02 | 중복 재료 추가 방지로 데이터 일관성 유지 |

### 4.4 보안

| ID | 요구사항 |
|----|----------|
| NFR-SEC-01 | 비밀번호 평문 저장 금지 (해싱 필수) |
| NFR-SEC-02 | 인증 토큰 SecureStore 저장 (AsyncStorage 사용 금지) |
| NFR-SEC-03 | API 키 환경 변수 관리 (.env, 코드에 하드코딩 금지) |

### 4.5 확장성

| ID | 요구사항 |
|----|----------|
| NFR-EXT-01 | 레시피 데이터를 외부 API로 교체할 수 있는 구조 |
| NFR-EXT-02 | AI 응답 모듈을 LLM API로 교체할 수 있는 구조 |
