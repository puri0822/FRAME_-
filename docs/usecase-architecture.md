# 요리조리 (Yorijori) — 유스케이스 & 시스템 아키텍처

---

## 1. 서비스 개요

**요리조리**는 냉장고 재료를 등록·관리하고, 보유 재료 기반으로 레시피를 추천하는 React Native / Expo 모바일 앱이다.

---

## 2. 액터 (Actors)

| 액터 | 설명 |
|------|------|
| **비로그인 사용자** | 앱을 처음 실행한 상태 (인증 없음) |
| **로그인 사용자** | 이메일/비밀번호 인증을 완료한 상태 |
| **AI 채팅봇** | 키워드 룰 기반 응답 시스템 (내부 시스템 액터) |

---

## 3. 유스케이스 다이어그램 (텍스트 표현)

```
[비로그인 사용자]
  ├── UC-01  회원가입
  └── UC-02  로그인

[로그인 사용자]
  ├── 냉장고 관리
  │     ├── UC-03  재료 추가
  │     ├── UC-04  재료 삭제
  │     ├── UC-05  유통기한 임박 재료 확인
  │     └── UC-06  카테고리별 재료 필터링
  ├── 레시피 탐색
  │     ├── UC-07  레시피 검색 (요리명·재료명)
  │     ├── UC-08  카테고리 필터
  │     ├── UC-09  레시피 상세 보기
  │     ├── UC-10  즐겨찾기 등록/해제
  │     └── UC-11  SNS 트렌딩 레시피 확인
  └── AI 채팅
        ├── UC-12  자유 텍스트 질문
        └── UC-13  빠른 칩으로 질문

[AI 채팅봇]
  └── UC-14  키워드 매칭으로 레시피 응답 생성
```

## 4. 유스케이스 명세

### UC-01 회원가입

| 항목 | 내용 |
|------|------|
| 주 액터 | 비로그인 사용자 |
| 목적 | 앱 계정 생성 |
| 사전 조건 | 앱 실행 |
| 기본 흐름 | 1. 이름(2자↑), 이메일, 비밀번호(6자↑), 비밀번호 확인 입력 → 2. 약관 동의 체크 → 3. 회원가입 버튼 → 4. 로그인 화면 이동 |
| 예외 흐름 | 유효성 실패 시 Alert 표시 / 비밀번호 불일치 시 오류 |
| 현재 구현 상태 | 시뮬레이션 (실제 API 미연결) |

## 5. 시스템 아키텍처

### 5-1. 전체 레이어 구조

```
┌─────────────────────────────────────────────────────────┐
│                     Presentation Layer                   │
│  app/_layout.js          (SafeAreaProvider + Stack)      │
│  app/auth/login.js       로그인 폼                       │
│  app/auth/signup.js      회원가입 폼                     │
│  app/(tabs)/home.js      AI 채팅 화면                    │
│  app/(tabs)/fridge.js    냉장고 재료 관리                 │
│  app/(tabs)/explore.js   레시피 탐색                     │
├─────────────────────────────────────────────────────────┤
│                      State Layer                         │
│  useState (각 화면 로컬)                                  │
│  - 재료 목록, 즐겨찾기: in-memory (비영속)               │
│  - 인증 상태: 없음 (세션 유지 미구현)                    │
├─────────────────────────────────────────────────────────┤
│                      Logic Layer                         │
│  AI_RULES 키워드 매칭  (home.js 내부)                    │
│  유통기한 계산 getExpiryInfo()  (fridge.js 내부)         │
│  레시피 검색·필터  (explore.js 내부)                     │
├─────────────────────────────────────────────────────────┤
│                      Style Layer                         │
│  styles/colors.js        공통 색상 상수 (C)              │
│  styles/tabs/home.js     홈 화면 스타일                  │
│  styles/tabs/fridge.js   냉장고 화면 스타일              │
│  styles/tabs/explore.js  탐색 화면 스타일                │
│  styles/auth/login.js    로그인 스타일                   │
└─────────────────────────────────────────────────────────┘
```

---

### 5-2. 라우팅 구조

```
/ (app/_layout.js — Stack)
├── auth/  (auth/_layout.js — Stack, headerShown: false)
│     ├── index.js   → redirect to /auth/login
│     ├── login.js
│     └── signup.js
└── (tabs)/  (_layout.js — Tabs, 하단 탭 바)
      ├── index.js   → redirect to /(tabs)/home
      ├── home.js    탭: 홈 (AI 채팅)
      ├── fridge.js  탭: 냉장고
      ├── explore.js 탭: 탐색
      └── main.js    href: null (숨김, 미사용)
```

앱 최초 진입 시 `/auth/login`으로 이동하며,  
인증 지속성(AsyncStorage / Context)은 **미구현** — 앱 재시작마다 로그인 필요.

---

### 5-3. 주요 데이터 흐름

#### 냉장고 재료 관리
```
사용자 입력 (Modal)
  → useState: ingredients[]  ←→  추가/삭제/필터
  → 화면 렌더링
  ✗ AsyncStorage 연결 없음 → 앱 종료 시 데이터 소실
```

#### 레시피 탐색
```
RECIPES[] (하드코딩, 10개)
  → 검색어 / 카테고리 필터 → useState: filtered[]
  → 카드 목록 렌더링
  → 탭: RecipeModal (바텀 시트)
  → 즐겨찾기: useState: Set<id>  (in-memory)
```

#### AI 채팅
```
사용자 입력 (TextInput / 빠른 칩)
  → getFakeResponse(text): AI_RULES 순차 매칭
  → messages[] 배열에 { role, text } 추가
  → ScrollView 자동 스크롤
```

---

### 5-4. 컴포넌트 구성 원칙

- **컴포넌트 범위**: 별도 components/ 디렉터리 없음. 모달·아이콘 등 모두 각 화면 파일 내 로컬 함수 컴포넌트로 정의.
- **아이콘**: 외부 아이콘 라이브러리 없이 `react-native-svg`로 인라인 SVG 직접 정의.
- **스타일**: 공통 색상은 `styles/colors.js`의 `C` 상수로 통일, 레이아웃 스타일은 화면별 스타일 모듈로 분리.
